# Przegląd PR i issues — 1 listopada 2026

Wersja aplikacji: 1.0.0. Zakres: integracja PR #10–#12 i #14–#22 oraz wybór A/B SQLite/PostgreSQL. Zgoda właściciela na scalenie do main została udzielona w rozmowie.

## Poprawki po przeglądzie

- #10: eksport roboczego JPK_KR_PD nie ustawia gotowości; dodatkowo usuwa wcześniejszy znacznik gotowości dla tego roku. Brak JPK_ST_KR jest jawny.
- #11: operator PostgreSQL dopisuje audyt, ale nie może go edytować/usuwać; preflight sprawdza efektywne prawa dziedziczone. To nie zamyka ryzyka omijania aplikacji przez bezpośredni SQL.
- #12: nieudane otwarcie ksiąg zwalnia blokadę operatora; zachowano samodzielną pracę SQLite.
- #14: dokumentacja rozróżnia JPK_KR_PD i brak JPK_ST_KR, bez automatycznego uznawania zwolnienia.
- #15: rozdzielone ustawienie i sprawdzenie klucza SQLCipher, izolacja kluczy kontekstów, regresja wielokrotnego tworzenia kontekstów EF.
- #16: zdalne S3 wymaga HTTPS, HTTP wyłącznie dla emulatora loopback.
- #17: ucięta odpowiedź KSeF lub przekroczona liczba stron kończy się błędem, bez deklarowania pełnej synchronizacji.
- #18: awaria zdalnego uploadu nie uruchamia retencji lokalnych kopii. Późniejszy udany backup lokalny może uruchomić retencję; nie jest to polityka wymagająca trwałego potwierdzenia replikacji wszystkich kopii.
- #19: test uszkodzonego JSONL rzeczywiście dochodzi do importu i sprawdza rollback, nie tylko preflight.
- #20: dodano brakującą obsługę potwierdzenia podstawy na ekranie płac, osobny dowód i świadome zaznaczenie; zmiana pozycji zeruje potwierdzenie formularza. Poprawiono regresję testu kadr. Nie deklarujemy pełnej obsługi art. 36–43.
- #21: prywatne uprawnienia pliku rejestru na Unix, odrzucenie bezpośrednich dowiązań; nie gwarantuje ochrony przed użytkownikiem mogącym zapisywać plik.
- #22: testy PostgreSQL na Windows; kontrola pominięć dopuszcza wyłącznie konkretny test emulatora S3 wykonywany na Linux, pozostałe pominięcia są błędem.
